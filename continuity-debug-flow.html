Continuity Extension Debug Flow

This file explains how the current VS Code extension works from activation to command execution, where state is stored, and what to check when the extension does not show up in Extension Development Host.

Project Type

VS Code extension written in TypeScript.

package.json contributes commands and points VS Code to out/extension.js.

Entry Point

src/extension.ts exports activate() and deactivate().

The compiled runtime file is out/extension.js.

Storage

Local SQLite via sql.js.

Database file: context.globalStorageUri/continuity.sqlite.

Activation Flow

1. VS Code reads package.json

Important fields:

main: "./out/extension.js"

activationEvents: ["onStartupFinished", "onCommand:..."]

down

2. Extension host loads out/extension.js

This is generated by npm run compile from src/extension.ts.

down

3. activate(context) runs

Creates an output channel, initializes the database, creates repository/status bar/file watcher, then registers commands.

down

4. Runtime services become active

TaskRepository handles persistence, ContinuityStatusBar displays active task state, and FileWatcher listens for document edits.

Command Flow

Command Palette Label Command ID Source File What It Does
Continuity: Start Task continuity.startTask src/commands/startTask.ts Prompts for a task name, creates a new active task, stores a goal event, updates status bar.
Continuity: Save Context Snapshot continuity.snapshotTask src/commands/snapshotTask.ts Saves selected text or pasted notes as a snapshot event on the active task.
Continuity: Continue Task In... continuity.continueTask src/commands/continueTask.ts Flushes pending file edits, builds the handoff prompt, copies it to clipboard.
Continuity: End Task continuity.endTask src/commands/endTask.ts Flushes pending file edits, marks active task completed, hides status bar.

Data Flow

Task state

TaskRepository.createTask() writes to task and event.

File edits

FileWatcher.onDidChangeTextDocument() stores before/after text in memory, then writes a unified diff after the debounce interval.

Prompt generation

buildHandoffPrompt() reads task, events, snapshots, touched files, and recent diffs from the repository.

Delivery

copyPromptToClipboard() writes the final Markdown prompt to the VS Code clipboard.

If You Cannot See The Extension In Dev Mode

Use this checklist inside the Extension Development Host window opened by F5.

  1. Confirm compile output exists: out/extension.js must exist. Run npm run compile if it does not.
  2. Start the right debug config: in Run and Debug, choose Run Continuity Extension. It uses --extensionDevelopmentPath=${workspaceFolder}.
  3. In the Extension Development Host, open Command Palette and search exactly: Continuity: Start Task.
  4. Check whether the extension activated: run Developer: Show Running Extensions and search for Continuity.
  5. Check extension logs: open Output panel, choose Continuity from the dropdown. Database initialization errors are written there.
  6. Check Extension Host errors: open Developer: Toggle Developer Tools, then inspect the Console tab.
  7. If the command exists but nothing happens, verify storage initialization: the extension loads node_modules/sql.js/dist/sql-wasm.wasm from context.extensionPath.
  8. If file edits are not captured, make sure a task is active and you are editing a saved file inside an opened workspace folder. Untitled files, output/log documents, binary-looking documents, and files outside the workspace are ignored.

Where To Put Breakpoints

  • src/extension.ts: first line of activate().
  • src/storage/db.ts: inside initialize(), especially initSqlJs().
  • src/commands/startTask.ts: after showInputBox().
  • src/capture/fileWatcher.ts: inside onDidChangeTextDocument() and flushEdit().
  • src/injection/promptEngine.ts: inside buildHandoffPrompt().

Most Likely Failure Points

Extension does not appear in Command Palette

Likely causes: wrong debug window, compile did not produce out/extension.js, malformed package.json, or extension host failed before command registration.

Status bar does not show immediately

The status bar only appears after an active task exists. Run Continuity: Start Task first.

Edits are not in the handoff

Only saved workspace file documents are tracked, and capture requires an active task. Pending edits are flushed before handoff in the current code.

Database initialization failed

Check Output panel under Continuity. The usual suspect is failure to load sql-wasm.wasm from the extension path.
