Architecture

How it works

Four stages, all local. Nothing leaves your machine.

01

Passive session observation

Continuity silently reads your AI agent's output as it runs — monitoring messages, code, decisions, and constraints. No prompts, no tags, no config required from the developer. It just watches.

⚙ fully passive ⬡ reads, never writes
02

Context window limit detection

Continuity watches for the context limit signal from whichever tool you're in. The moment the session is about to be cut off, it triggers state capture — so nothing is lost in the truncation.

⚡ <1s capture ⚙ automatic trigger
03

Last known state serialization

The captured state is serialized into a structured, human-readable context packet — decisions made, artifacts created, in-flight tasks, anti-context, and hard constraints. Stored locally in SQLite. Inspectable at any time from the VSCode status bar.

⬡ local SQLite store ⚡ versioned + diff-able
04

You paste. New session resumes.

Continuity surfaces the state packet with one click — copy to clipboard. You paste it as the opening message in any new chat window: same tool, different tool, doesn't matter. The AI has full context. You never re-explain anything.

⚙ one-click copy ⬡ you control transfer

Context schema

What gets captured

Context is not just code snippets. Continuity captures the reasoning layer — decisions, constraints, and what not to do.

⊕

Architecture decisions

Structural choices made during the session — data models, service boundaries, design patterns adopted.

using turborepo monorepo
auth via asymmetric JWT
postgres as source of truth
⊗

Anti-context

Explicit rejections. Things the AI must not suggest again — failed approaches, banned dependencies, ruled-out patterns.

DO NOT use redis
reason: race conditions at load
DO NOT suggest graphql
⊘

In-flight reasoning chains

Incomplete explorations — hypotheses under investigation, multi-step plans partway through execution.

evaluating: lru → pg strategy
step 2/4 complete
next: write-through job
⊡

Hard constraints

Non-negotiable requirements: performance targets, compliance boundaries, environment limits, team conventions.

p99 latency < 80ms
no cloud egress (on-prem)
java 17 target
⊞

Dependency graph snapshot

Libraries, versions, and inter-service dependencies relevant to the current task — pulled from workspace metadata.

spring-boot: 3.2.0
turborepo: 1.11
@auth/service → @db/core
⊟

Generated artifacts

Code, configs, and diffs produced in the session — referenced by file path so they don't bloat the transfer payload.

src/auth/middleware.ts (new)
config/jwt.yaml (modified)
ref: session-d4f7b
